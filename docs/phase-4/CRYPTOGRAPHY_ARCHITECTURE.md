# ARC Vault Cryptography Architecture

## 1. Cryptographic Primitive Selection

The encrypted vault utilizes industry standard, authenticated encryption algorithms:

- **Symmetric Cipher:** `AES-256-GCM` (`AES/GCM/NoPadding`)
- **Key Length:** 256 bits (32 bytes)
- **Initialization Vector (Nonce):** 96 bits (12 bytes) cryptographically secure random bytes per operation (`java.security.SecureRandom`)
- **Authentication Tag Length:** 128 bits (16 bytes)
- **Key Derivation Function (KDF):** `PBKDF2WithHmacSHA256`
- **PBKDF2 Iteration Count:** 100,000 iterations (OWASP recommendation for mobile credentials)
- **KDF Salt Length:** 256 bits (32 bytes)

---

## 2. Envelope Specification

Every encrypted value (both note titles and note payloads) is packaged into a self-contained, authenticated byte envelope prior to Base64 encoding:

```
+----------------+--------------------------+-------------------------------------+
| Version (1 B)  | IV / Nonce (12 Bytes)    | Ciphertext + GCM Tag (N + 16 Bytes) |
+----------------+--------------------------+-------------------------------------+
```

- **Byte 0 — Version:** `0x01` representing envelope specification V1. Enables future crypto agility (e.g. migration to Argon2id or post-quantum primitives) without breaking existing envelopes.
- **Bytes 1–12 — Nonce:** Unique 12-byte random IV generated per encryption invocation.
- **Bytes 13..End — Ciphertext & AEAD Tag:** Authenticated ciphertext terminating with the 16-byte GCM authentication tag.

---

## 3. Threat Mitigations by Design

1. **Replay & Chosen-Ciphertext Attacks:**
   The 128-bit authentication tag covers the entire payload. Any tampering with a single bit of the version byte, IV, or ciphertext immediately triggers an `AEADBadTagException` during `cipher.doFinal()`, rejecting corrupted data.
2. **Nonce Reuse Prevention:**
   A new 96-bit random nonce is generated by `SecureRandom` on every single save or update. Identical plaintexts encrypted with the same key produce completely different ciphertexts.
3. **Timing Attack Resistance:**
   Constant-time byte comparison (`constantTimeEquals`) is used for credential checks to prevent timing-oracle attacks.
4. **Offline Brute-Force Resistance:**
   Even for a short 3-digit PIN, PBKDF2 HMAC-SHA256 with 100,000 iterations forces extensive computation per guess (~30–50ms on modern mobile CPU hardware).
